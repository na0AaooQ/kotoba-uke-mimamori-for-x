# ワンクッションのガイダンス機能の設計意図

## 対象と目的

この資料は、Google Chrome 拡張機能「ことばうけみまもり｜Xことばに心のワンクッション」におけるワンクッションのガイダンス機能について、将来の保守担当者のために設計意図と境界を記録するものです。

ガイダンスは、本文を開く前に、利用者が「どのような強さ・傾向の表現かもしれないか」を少し想像し、今読むか、今は読まないか、あとで読むかを自分で考えるための補助情報です。利用者の判断を代行するものではなく、投稿者やアカウントを評価する機能でもありません。

## 情報設計

ワンクッションには、固定ルールによる補助的な情報として、次の二種類を表示できます。

- 表現の強さの目安
- 検知された表現の傾向

利用者向け UI は内部の判定結果を直接表示せず、必要最小限の表示用キーだけを受け取ります。これにより、内部実装の詳細、投稿本文、投稿者への評価に見える情報を画面へ出さない境界を維持します。

## 生の数値 score を表示しない理由

内部の `score` は、ブラウザ内の固定ルールによる加点・減点の結果です。危険である確率、被害が発生する確率、AI の信頼度・確信度、投稿者の攻撃性や悪意を示す割合、投稿内容の事実である確率、医学的・心理的な危険度、法律上の違法性を示す値ではありません。

したがって、`score` が 100 であっても「100%危険」「100%攻撃的」という意味ではありません。生の数値を利用者へ直接表示すると、固定ルールによる補助判定以上に精密な測定結果、危険度、確率、または AI の信頼度であるかのように受け取られるおそれがあります。

このため、生の `score` は利用者向け UI に表示せず、三段階の「表現の強さの目安」へ抽象化します。これは精密さを過剰に提示せず、利用者へ必要以上の断定をしないための設計判断です。

## 表現の強さの目安

`cushion-guidance.js` は、正規化した内部 score から次の表示用 `strengthKey` を生成します。

| score | strengthKey | 日本語 UI | English UI |
| --- | --- | --- | --- |
| 0〜59 | なし | 表示しない | Not shown |
| 60〜79 | `somewhatStrong` | やや強め | Somewhat strong |
| 80〜89 | `strong` | 強め | Strong |
| 90〜100 | `veryStrong` | かなり強め | Very strong |

この三段階は、危険度・被害の深刻度・投稿者の攻撃性のランキング、投稿者の人格評価、AI の確信度ではありません。固定ルールによる内部 score を、本文を開く前の判断材料にできるよう抽象化した補助的な目安です。

## 感度設定と強さの目安の関係

感度設定は、ワンクッションを表示するしきい値だけを変更します。現在の内部しきい値は次のとおりです。

| 表示ラベル | 内部値 | しきい値 |
| --- | --- | ---: |
| 少なめ | `low` | 100 |
| 標準 | `standard` | 80 |
| 多め | `high` | 60 |

感度設定は同じ本文の score そのものを変更しません。そのため、同じ本文では、同じ score から同じ `strengthKey` が生成されます。感度設定が変えるのは「ワンクッションを表示するかどうか」であり、同じ表現の強さの意味ではありません。この関係は工程4の統合・回帰テストで保証します。

## 検知された表現の傾向

利用者へ内部カテゴリをそのまま表示せず、次の安全な表示用カテゴリを使います。

| tendencyKey | 日本語 UI | English UI |
| --- | --- | --- |
| `personalSafety` | 身の安全に関わる可能性のある表現 | Language that may relate to personal safety |
| `privacy` | 個人情報やプライバシーに関わる可能性のある表現 | Language that may relate to personal information or privacy |
| `circumstancesOrBackground` | 人の立場や背景などに関わる強い表現 | Strong language related to someone's circumstances or background |
| `directedStrongLanguage` | 人に向けた強い表現 | Strong language directed at someone |
| `possiblyPressuringLanguage` | 圧を感じる可能性のある表現 | Language that may feel pressuring |

「圧」の感じ方は利用者や状況によって異なります。そのため、「圧のある表現」と断定せず、「圧を感じる可能性のある表現」という非断定的な表現を採用しています。

### 内部カテゴリから表示カテゴリへの変換

`cushion-guidance.js` は、内部カテゴリを次のように変換します。

| 内部カテゴリ | 表示用 tendencyKey |
| --- | --- |
| `threat_or_harm` | `personalSafety` |
| `doxxing_or_privacy_risk` | `privacy` |
| `discriminatory_attack` | `circumstancesOrBackground` |
| `existence_denial`、`personality_attack`、`severe_insult` | `directedStrongLanguage` |
| `persistent_attack` | `possiblyPressuringLanguage` |

BOOST や DEDUCTION など、利用者向け表示に不要な内部情報は表示カテゴリへ変換しません。未知の内部カテゴリは安全に無視します。

### 最大2件に限定する理由

検知された表現の傾向は最大2件まで表示します。本文を開く前の補助情報として情報量を増やしすぎず、ワンクッション UI の主目的を損なわず、利用者に過度な情報負荷を与えない、読みやすい範囲に留めるためです。

### 表示優先順位の意味

傾向の表示優先順位は、次のとおりです。

1. `personalSafety`
2. `privacy`
3. `circumstancesOrBackground`
4. `directedStrongLanguage`
5. `possiblyPressuringLanguage`

これは、危険度・深刻度・被害の大小・投稿者の攻撃性のランキングではありません。本文を開く前の利用者にとって、どの情報を先に知ることが判断材料として役立つかを考えた UI 上の表示優先順位です。

## 表示情報の安全な境界

情報の経路は次のとおりです。

```text
risk-detector.js
  ↓ 生の riskResult
cushion-guidance.js
  ↓ 安全な strengthKey / tendencyKeys
content.js
  ↓ targetNode 単位の一時的な受け渡し
overlay.js
  ↓ 表示許可されたキーのみ UI 表示
```

`content.js` は `WeakMap` で targetNode ごとに安全なガイダンスだけを一時的に関連付け、描画後に削除します。引用する側の投稿と引用元投稿は別の targetNode として扱うため、score・`strengthKey`・`tendencyKeys`、表示・解除操作が相互に伝播しません。投稿ごとに独立した判断材料を提供するためです。

`overlay.js` は表示可能な `strengthKey` と `tendencyKeys` をホワイトリスト方式で限定します。未知値・不正値・重複値は安全に無視し、ガイダンスがない場合は従来のワンクッション UI を維持します。

UI へ生の判定結果を直接渡さず、次の情報を利用者向け表示に使いません。

- 生の `score`
- 生の `categories`
- `reasons` の内部詳細
- `matchedRules`
- `riskLevel`
- `shouldCushion`
- 投稿本文
- URL
- X ユーザー情報

## 保存・外部送信をしない理由

ガイダンス機能を追加しても、既存のプライバシー設計を弱めません。投稿本文、score、categories、reasons、matchedRules、riskLevel、shouldCushion、guidance、strengthKey、tendencyKeys、URL、X ユーザー情報を新たに永続保存しません。Chrome Storage、Local Storage、IndexedDB、DOM data 属性へこれらを保存しません。

投稿本文や判定結果を、外部 AI や外部サーバーへ送信しません。現在保存するのは既存仕様の設定値だけです。

## 「今は見ない」後にガイダンスを非表示にする理由

利用者が「今は見ない」を選んだ時点で、今は本文を読まない判断をしています。その後も強さや傾向を表示し続けると、再び判断を迫ったり、本文を確認する方向へ興味を引いたり、その選択の余白を狭めたりする可能性があります。

そのため、選択後はガイダンスを取り除き、「今は読まないようにしました」「読みたくなったら、あとから内容を表示できます」という簡潔な状態にします。

## UIの色や視覚表現を強さごとに変えない理由

強さの段階に応じた赤色警告、危険アイコン、警告ゲージ、プログレスバー、強い色分けは行いません。危険度判定のように見えること、利用者を必要以上に不安にさせること、数値的・医学的・法律的な危険判定と誤認されることを避け、強さの違いは穏やかな文字情報で伝えるためです。

## AI判定ではないこと

この機能は、外部 AI や生成 AI による文章理解・意味推定ではありません。ブラウザ内の固定ルールとスコアリング方式による補助判定であり、誤検知や見逃しが発生する可能性があります。

ガイダンスは、投稿の危険性を断定するもの、投稿内容の事実関係を判定するもの、投稿者の人格や悪意を評価・推定するもの、法律判断、医療判断、心理診断ではありません。ワンクッションやガイダンスの表示回数だけで、相手の人格・意図・アカウントの危険性・攻撃性を評価することもできません。利用者が感じている負担や、今後どの程度距離を取りたいかを考える材料にはできますが、相手を自動的に評価する機能にはしません。

## 検討した代替案と見送り理由

### 生 score・パーセンテージを表示する案

score は危険度・確率・AI 信頼度ではありません。固定ルール判定以上の精密さを過剰に提示し、100 を「100%危険」と誤解される可能性があるため、生 score とパーセンテージ表示は採用しませんでした。

### 危険度ゲージ・プログレスバーを表示する案

数値的な危険判定や精密な測定結果のように見えるため、採用しませんでした。

### 強さごとの警告色を使う案

利用者の不安を必要以上に強め、危険度判定のように見える可能性があるため、採用しませんでした。

### 内部カテゴリをそのまま表示する案

内部実装の分類を利用者へ直接見せると、断定的・専門的に見えたり、投稿者評価につながったりする可能性があるため、利用者向けに抽象化した表示カテゴリを採用しました。

### すべての傾向を表示する案

本文を開く前の補助情報としては情報量が増えすぎ、利用者の負担になる可能性があるため、最大2件に限定しました。

### 「今は見ない」後もガイダンスを残す案

すでに利用者が選んだ「今は読まない」という判断を尊重し、再び判断を迫らないため、採用しませんでした。
